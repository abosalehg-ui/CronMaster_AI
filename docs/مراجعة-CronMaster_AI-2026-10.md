## 1. نظرة عامة سريعة

CronMaster_AI أداة مراقبة وإصلاح ذاتي للمهام المجدولة (cron jobs). تجيب المهام من واجهة خلفية (backend): OpenClaw CLI أو `crontab`، وتصنّف أسباب الفشل بمطابقة أنماط (regex) مع مصنّف Claude اختياري، وتطبّق إصلاحات بسقف محدد (رفع المهلة، إعادة المحاولة، التراجع، قاطع الدائرة، إزاحة الجدولة). بعدها ترسل تنبيهات على Telegram وSlack وDiscord وWebhook، مع فترة هدوء (quiet hours). وتحفظ سجل تاريخي في SQLite يطلع منه `stats` وتقرير HTML.

**البنية:** `cli` ← `core` (منسّق، 445 سطر) ← `policies` (سياسات الإصلاح الخمس) ← `fixers` / `backends` / `notifiers` / `storage` / `analysis` / `reporting` / `metrics`. الاعتماديات تمشي في اتجاه واحد، ومحد يستورد `cli`.

**التقنيات:**
- Python ≥ 3.9، **بدون أي اعتمادية تشغيل**. المكتبة القياسية بس، وCI يتحقق من هذا باختبار دخان (smoke test).
- اعتماديات اختيارية: `anthropic>=0.40` للمصنّف الذكي، و`pytest` و`ruff` للتطوير.
- SQLite و`urllib` و`fcntl` و`zoneinfo`، والرسوم البيانية SVG مكتوبة يدويًا.
- CI يختبر على Python 3.9 و3.11 و3.13، وفيه job ثانية تثبّت الحزمة وتشغّل `cronmaster --version`.

**أكبر الملفات:** `storage.py` (720)، `core.py` (445)، `cli.py` (430)، `i18n.py` (411)، `analysis/llm.py` (368)، `reporting/html.py` (356)، `config.py` (349)، `policies.py` (314).

## 2. المراجعة التقنية والهندسية (45%)

### 2.1 البنية المعمارية وفصل المسؤوليات — **9/10**

استخراج `PolicyEngine` إلى `policies.py` نزّل `core.py` من 641 إلى 445 سطر، وصارت `monitor()` حلقة تنسيق مقروءة. السياسات الخمس صار لها نقطة دخول وحدة مرتّبة بوعي:

```python
if self.check_circuit_breaker(job, analysis, dry_run):
    fixes = 1
elif self.check_rollback(job, analysis, dry_run):
    fixes = 1
elif auto_fix and analysis.auto_fixable:
    fixes, retries = self.apply_auto_fix(...)
```

عقد القدرات (Capability contract) في `backends/base.py` باقي أقوى قرار في المشروع.

**ملاحظة بنيوية واحدة** — في `cli.main()` يُبنى `CronMaster` قبل ما يُؤخذ القفل:

```python
master = CronMaster(dry_run=...)        # يحمّل state.json هنا
...
if args.command == "monitor":
    sys.exit(_run_monitor(master, args))  # والقفل يُؤخذ هنا
```

يعني الحالة تنقرا **خارج** القفل. والأوامر اللي تعدّل الحالة غير `monitor`، وهي `fix` و`restore`، ما تاخذ القفل أبدًا (تفاصيلها في 4.6).
**الحل:** أخذ `ExecutionLock` في `main()` قبل بناء `CronMaster` للأوامر `monitor` و`fix` و`restore`.

### 2.4 معالجة الأخطاء والحالات الحدّية — **6/10** ← أضعف نقطة هندسيًا

المشروع ممتاز في `BackendError`، بس **أي استثناء ثاني** يطيّح دورة المراقبة كاملة، ويضيع معه مسار «فشل المراقب حدث صريح».

#### 🟠 (أ) `monitor()` يحمي `list_jobs()` من `BackendError` بس

`core.monitor()`:

```python
try:
    all_jobs = self.backend.list_jobs()
except BackendError as e:
    ...  # تنبيه حرج + مقاييس فشل
```

وبعدها حلقة المهام ما فيها أي حماية:

```python
for index, job in enumerate(failed_jobs, start=1):
    analysis = self.analyzer.analyze(job)
    fixes, job_retries = self.policies.handle_failure(...)
```

مسارين أكدتهم بالتجربة:

1. **`analysis/llm.py` — `_ask()`** يلتقط أربعة أصناف بس: `AuthenticationError` و`RateLimitError` و`APIStatusError` و`APIConnectionError`. في حين أن `pyproject.toml` يسمح بـ `anthropic>=0.40`، وهذي نسخة قديمة جدًا وأقدم من دعم `output_config`. المعامل غير المعروف يرفع `TypeError`:
   > **نتيجة الفحص:** `LLM CRASH TypeError create() got an unexpected keyword argument 'output_config'`، والدورة كلها توقفت. ما انحفظت الحالة، ولا انرسل تنبيه عن المهام الفاشلة الثانية، ولا انكتبت مقاييس Prometheus.

2. **`backends/openclaw.py` — `list_jobs()`**: لو رجع JSON صالح بس شكله غير متوقع:
   ```python
   jobs_data = data.get("jobs", data) if isinstance(data, dict) else data
   for job in jobs_data:
       jobs.append(self._parse_job(job))   # job هنا نص (مفتاح قاموس)
   ```
   > **نتيجة الفحص:** `{"items": []}` تعطي `AttributeError: 'str' object has no attribute 'get'`. والمفروض تطلع `OpenClawError`.

في الحالتين `cli.main()` يلتقط الاستثناء ويطلع بالكود 1، **بس** ما ينرسل التنبيه الحرج «CronMaster لا يستطيع قراءة المهام»، ونبضة healthcheck تنقطع بدل ما تروح إلى `/fail`.

**الحل:**
- في `openclaw._parse_job`: إذا `jobs_data` مو قائمة أو أي عنصر مو `dict`، ارفع `OpenClawError("شكل مخرجات غير متوقع")`.
- في `llm._ask`: أضف `except Exception` أخير (يسجّل ويرجّع `None`) مثل ما يسوي `_get_client` أصلًا، وارفع الحد الأدنى لـ `anthropic` إلى نسخة تأكدت أنها تدعم `output_config`.
- في `core.monitor`: غلّف معالجة كل مهمة بـ `try/except Exception` يسجّل ويكمّل، عشان مهمة وحدة ما تطيّح مراقبة البقية.

#### 🟠 (ب) تسجيل «نُبِّه» يصير قبل ما ينرسل التنبيه فعلًا

`policies._timeout_flow` و`policies.check_duration_regression`:

```python
if dry_run or self.state.should_alert(job.id, "futile_fix"):
    self.escalate(analysis.fix_details)
    if not dry_run:
        self.state.record_alert(job.id, "futile_fix")   # ← قبل الإرسال
```

`escalate()` تضيف السطر لقائمة `notices` بس، والإرسال الفعلي يصير بعدين في `core._maybe_alert()`. يعني التهدئة تتسجّل حتى لو:
- شُغّل `monitor --no-alert`، فما في إرسال أصلًا.
- فشلت كل القنوات، مثلًا Telegram واقف.
- كنا في فترة الهدوء.

> **نتيجة الفحص:** (1) ثلاث دورات وكل القنوات تفشل: `ALERTS_RECORDED {'j1/futile_fix': ...}` مع إن ولا رسالة وصلت. (2) دورتين بـ `--no-alert` وبعدها دورة عادية: `FUTILE_IN_NOTICES False`، يعني التحذير اختفى 24 ساعة بدون ما يشوفه أحد.

قارنها بـ `core._maybe_alert()` نفسها. هناك التسجيل يصير صح، **بعد** نجاح الإرسال:

```python
if not self.alerter.send(message, critical=bool(critical)):
    return False
for a in alert_analyses:
    self.state.record_alert(a.job.id, a.error_type.value)
```

**الحل:** `PolicyEngine` يجمع `pending_alerts: List[Tuple[job_id, kind]]` بدل ما يسجّل بنفسه، و`_maybe_alert` تسجّلها مع الباقي بعد نجاح `send`.

#### 🟡 (ج) `cli history --limit 0` يرجّع السجل كامل

`storage.get_history()`: `fixes_applied[-limit:]`، و`[-0:]` تعطي القائمة كلها. وبالمثل الأرقام السالبة.
**الحل:** `hist.add_argument("--limit", type=_positive_int, ...)`.

### 2.5 الأداء واستهلاك الموارد — **8/10**

الإصلاحات السابقة حقيقية: استعلام تجميعي واحد لكل المهام، و`executemany` في معاملة وحدة، ونافذة `LIMIT 50` في `_rows`. اللي باقي مقبول:
- `job_summaries()` ما زالت تسوي استعلام **مسقوف** لكل مهمة (N+1 بسقف 50 صف). يكفي لعشرات المهام، ومع مئات المهام يصير محسوس. `ROW_NUMBER() OVER (PARTITION BY job_id ...)` يجيب كل النوافذ في استعلام واحد.
- `crontab.run_job()` يشغّل المهمة **متزامنًا** بمهلة 300 ثانية داخل دورة المراقبة. ثلاث إعادات محاولة ممكن تعلّق الدورة 15 دقيقة. يُستحسن تشغيلها بـ `Popen` منفصل بدون انتظار، أو بمهلة أقصر.

## 3. المظهر والتصميم وتجربة المستخدم (30%)

> المشروع أداة CLI ومعه تقرير HTML. عدّلت المعيار مثل ما يطلب الرابرك: وضوح مخرجات الطرفية، ورسائل الخطأ، و`--help`، وi18n، وفوقها RTL وإمكانية الوصول في تقرير HTML.

### 3.1 وضوح مخرجات الطرفية — **8/10**

العرض البشري الجديد لـ `monitor` و`list` و`fix` و`history` نقلة واضحة: ملخص بمحاذاة محسوبة من `display_width`، وبعده كتلة لكل مهمة فاشلة، مع JSON تلقائي لما تكون المخرجات مو طرفية. ينقصه بس أن `stats` و`status` ما يدعمون `--json`، وهذا خلاف بقية الأوامر.

### 3.2 جودة رسائل الخطأ — **8/10**

أغلب الرسائل تشرح وش صار ووش الحل، مثل «TELEGRAM_CHAT_ID غير مضبوط — اضبطه في config.json أو...». الاستثناء الوحيد: الاستثناءات اللي في 2.4 (أ) تطلع للمستخدم كسطر «خطأ غير متوقع» عام بدل رسالة تشرح السبب.

### 3.3 جودة `--help` — **7/10**

`cli.build_arg_parser()` يُبنى **قبل** ما تُقرأ `--lang`، فكل نصوص المساعدة عربية حتى مع `--lang en`. والوصف والأمثلة ما تزال تقول `"مدير ذكي لـ OpenClaw Cron Jobs"` مع إن crontab مدعوم.
**الحل:** نصوص `help=` بالإنجليزية والعربية جنب بعض، أو مسح مبكر لـ `sys.argv` يدور على `--lang` قبل بناء المحلّل.

### 3.4 العربية و RTL (تقرير HTML) — **8/10**

فيه `<html lang dir>` ديناميكي، و`text-align: start` بدل `left`، و`Noto Naskh Arabic` كخط احتياطي بدون تحميل خارجي، والأرقام عربية (0–9) بشكل متسق في كل مكان. التقرير مكتفي بنفسه بدون أي طلب شبكة.

### 3.5 إمكانية الوصول — **7/10**

بند الجولة الأولى رقم 16 (`scope` و`caption` و`data-label`) انطبق على `_jobs_table` و`_history_table` **بس**. جدول «المهام الفاشلة» في `render_html()`، وهو أهم جدول في التقرير، ما زال كذا:

```python
head = "".join(
    f"<th>{_e(h)}</th>"   # بلا scope="col"
    for h in (t("html.col_job"), t("report.error"), ...)
)
items = "".join(
    f"<tr><td>{_e(a.job.name)}</td>..."   # بلا data-label ولا class="wrap"
```

النتيجة: تحت عرض `34rem` يختفي `thead` ويعتمد التخطيط على `td::before { content: attr(data-label) }`. فعلى **الجوال** تطلع خلايا الجدول الفاشل **بدون أي تسمية**. وعلى سطح المكتب عمودَي الوصف والإصلاح عليهم `nowrap` فيصير تمرير أفقي. وقارئ الشاشة ما يربط الخلايا برؤوسها.
**الحل:** استخدم `_head([...], wrap=[2, 3])` و`data-label` في كل `td` مثل `_jobs_table` بالضبط، وأضف `<caption>`.

### 3.6 i18n — **7/10**

فحصت كل `.py` يدور على نص عربي يوصل للمستخدم بدون ما يمر على `t()`، ولقيت 6 مواضع، وفوقها مسار المصنّف الذكي:

| الموضع | النص المتسرّب في `--lang en` |
|---|---|
| `core.monitor()` — تنبيه فشل الواجهة الخلفية | `"🚨 CronMaster لا يستطيع قراءة مهام OpenClaw"`، وهو **أهم تنبيه** في الأداة، وكمان يذكر OpenClaw حتى مع crontab |

### 3.7 التغذية الراجعة والتأكيد — **7/10**

### 4.3 التحقق من المدخلات — **6/10**

#### 🔴 القيم المنطقية النصية في `config.json` تُقرأ عكس معناها

`Config.validate()` تتحقق من أنواع `_INT_KEYS` و`_FLOAT_KEYS` و`_STR_KEYS` و`NOTIFIERS` و`QUIET_HOURS`، **بس `_BOOL_KEYS` ما لها أي فحص**. ومسار البيئة يحوّل النص صح:

```python
elif attr in cls._BOOL_KEYS:
    setattr(cls, attr, env_value.strip().lower() in ("1", "true", "yes"))
```

أما مسار الملف فيمرّر القيمة كما هي:

```python
if attr in configurable:
    setattr(cls, attr, value)
```

> **نتيجة الفحص:** `{"circuit_breaker_enabled": "false"}` تعطي `CB 'false' True coerced []`. الخاصية **اشتغلت** بدون أي تحذير، ولا ظهرت في `doctor`.

ليش 🔴: الخطأ متوقع جدًا، لأن المستخدم اللي يكتب `"false"` بعلامتي تنصيص هو نفسه اللي ينسخ من متغيرات البيئة. والضرر هنا مو تجميلي: `circuit_breaker_enabled` و`auto_reschedule` و`rollback_timeout_enabled` كلها **تعدّل مهام المستخدم الحيّة** (تعطيل وإعادة جدولة). المستخدم حاول **يطفي** خاصية مدمّرة، فصارت **شغّالة**.
**الحل** في `validate()`، وهو يمشي على نفس فلسفة `_STR_KEYS`:

```python
_TRUE, _FALSE = ("1", "true", "yes"), ("0", "false", "no", "")

for attr in cls._BOOL_KEYS:
    value = getattr(cls, attr)
    if isinstance(value, bool):
        continue
    text = str(value).strip().lower()
    # نص معروف يُحوَّل لمعناه؛ أي شيء آخر يُعامَل false — الخيار الآمن
    # لأن أغلب المفاتيح المنطقية الخطرة (تعطيل/جدولة/تراجع) معطّلة افتراضياً
    parsed = text in _TRUE
    if text not in _TRUE + _FALSE:
        logger.warning("قيمة %s غير مفهومة (%r) — اعتُبرت false", attr, value)
    setattr(cls, attr, parsed)
    cls.coerced_keys.append(attr.lower())
```

#### 🟡 `shift_cron_expression()` تعكس اتجاه الإزاحة

**الحل:** إذا التفّت الدقيقة وحقل الساعة رقم، زِد الساعة `% 24`. وإذا الساعة `*` أو تعبير، ارفض الإزاحة (`return None`) مثل ما يسوي الكود مع الحالات الغامضة الثانية.
